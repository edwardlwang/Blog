数据结构是计算机存储、组织数据的方式。它决定了数据的访问效率、插入删除代价以及内存占用。不同的数据结构适用于不同的场景，没有“最好”的数据结构，只有“最合适”的数据结构。

本文按逻辑结构与物理存储两个维度，系统梳理常见数据结构，并给出复杂度速查表与选择指南。

---

## 一、按逻辑结构分类

逻辑结构描述数据元素之间的相互关系，与具体存储方式无关。

### 1. 线性结构

数据元素之间是一对一的线性关系。

- **数组（Array）**：连续内存，支持随机访问。
- **动态数组（Dynamic Array）**：可自动扩容的数组，如 C++ 的 `vector`。
- **链表（Linked List）**：节点通过指针相连。
  - 单链表
  - 双链表
  - 循环链表
- **栈（Stack）**：后进先出（LIFO）。
- **队列（Queue）**：先进先出（FIFO）。
  - 普通队列
  - 双端队列（Deque）
  - 循环队列
- **哈希表（Hash Table）**：通过哈希函数映射键值，逻辑上也可视为一种线性映射结构。

### 2. 树形结构

数据元素之间是一对多的层次关系。

- **二叉树（Binary Tree）**
- **二叉搜索树（BST）**
- **平衡二叉搜索树**
  - AVL 树
  - 红黑树
  - Splay 树
  - Treap
- **多路搜索树**
  - B 树
  - B+ 树
- **堆（Heap）**
  - 大顶堆
  - 小顶堆
- **Trie / 前缀树**
- **线段树（Segment Tree）**
- **树状数组（Fenwick Tree / BIT）**
- **并查集（Union-Find / Disjoint Set）**：本质是森林结构。

### 3. 图形结构

数据元素之间是多对多的网状关系。

- **有向图**
- **无向图**
- **加权图**
- 常见存储方式：
  - 邻接矩阵
  - 邻接表
  - 边集数组

### 4. 集合与散列结构

- **哈希集合（Hash Set）**
- **哈希映射（Hash Map）**
- **位图（Bitmap）**
- **布隆过滤器（Bloom Filter）**：概率型数据结构，存在误判但空间效率极高。
- **跳表（Skip List）**：以概率方式实现近似平衡的有序链表。

## 二、按物理存储分类

物理结构描述数据在内存中的实际组织方式。

| 存储方式 | 说明               | 典型结构             |
| -------- | ------------------ | -------------------- |
| 顺序存储 | 用连续内存存放数据 | 数组、动态数组、堆   |
| 链式存储 | 用指针连接离散节点 | 链表、树、图的邻接表 |
| 散列存储 | 通过哈希函数定位   | 哈希表、哈希集合     |
| 索引存储 | 附加索引表辅助查找 | B 树、B+ 树          |

## 五、如何选择数据结构

选择数据结构时，先问自己几个问题：

1. **需要快速随机访问吗？**  
   是 → 数组 / `vector`。

2. **需要频繁在中间插入删除吗？**  
   是 → 链表 / `list`。

3. **需要后进先出吗？**  
   是 → 栈 / `stack`。

4. **需要先进先出吗？**  
   是 → 队列 / `queue`。

5. **需要按优先级取元素吗？**  
   是 → 堆 / `priority_queue`。

6. **需要快速按键查找吗？**  
   是 → 哈希表 / `unordered_map`。

7. **需要有序遍历或范围查询吗？**  
   是 → 平衡树 / `map`、`set`，或 B+ 树。

8. **需要前缀匹配吗？**  
   是 → Trie。

9. **需要区间查询与更新吗？**  
   是 → 线段树 / 树状数组。

10. **需要判断连通性吗？**  
    是 → 并查集。

11. **需要表示多对多关系吗？**  
    是 → 图（邻接表或邻接矩阵）。

## 六、总结

数据结构可以按逻辑结构分为线性结构、树形结构、图形结构和集合散列结构；按物理存储分为顺序存储、链式存储、散列存储和索引存储。

实际工程中，很少从零实现这些结构，更多是理解它们的特性，然后选择合适的标准库容器或数据库索引结构。掌握复杂度与适用场景，比记住实现细节更重要。

一句话概括：

> **数据结构是算法的基础，选择对了，问题就解决了一半。**
